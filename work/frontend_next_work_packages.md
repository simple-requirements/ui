# Recommended next frontend work packages

## Recommendation

The next frontend work should stay close to backend APIs that already exist or are nearly complete. Avoid starting large future-backend areas such as baselines, verification, dashboards, users/roles, or variants until their backend contracts are available.

| Priority | Work package                                      | Stories                                                                 | Why next                                                                                                                                                                         | Main tasks                                                                                                                                                                                                               |
| -------- | ------------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1        | FE export controls for existing backend adapters  | FE-FR-IMEX-0001, FE-FR-MET-0006, FE-FR-REF-0005                         | Backend now exposes export formats and project/requirement export endpoints, and the frontend generated client already contains export models/endpoints.                         | Add export format discovery UI; support JSON, GitHub Markdown, and AsciiDoc; show PDF as unavailable/unresolved; add project export and selected-requirement export actions; implement progress/error/download handling. |
| 2        | FE requirement-link UX completion                 | FE-FR-REF-0001..0004, FE-FR-VER-0002                                    | The current source already has link create/update/delete, incoming/outgoing panels, history, and revision link-change comparison; it needs polish rather than a new domain area. | Add target search/select instead of raw key only; display category key/type/status in link rows; add simple overview/filter route; improve conflict/error messaging; add accessibility and e2e checks.                   |
| 3        | FE lifecycle metadata and detail correctness      | FE-FR-LIFE-0001..0006, FE-FR-WFLO-0003, FE-FR-REQ-0002, FE-FR-VIEW-0001 | Lifecycle actions exist, but detail pages do not expose enough decision metadata, and category names are not accurately mapped from the current requirement DTO.                 | Show approval/rejection/implementation/obsolescence metadata; improve 409 handling; resolve category-name display either by backend projection or client join with category cache; add tests for terminal states.        |
| 4        | FE search/filter foundation                       | FE-FR-SRCH-0001..0003, FE-FR-VIEW-0003                                  | The list and exact-key lookup already exist, but users cannot search/filter the requirement set effectively.                                                                     | Add full-text search input, combinable filters, URL state, active filter chips, cancellable/debounced requests, and table sorting/pagination/virtualization where needed.                                                |
| 5        | FE metric grammar and metric navigation hardening | FE-FR-MET-0001..0005                                                    | The frontend already parses inline metric definitions and renders values, but it needs alignment with the backend grammar and a real metric management/navigation UI.            | Align accepted metric-key grammar; add metric picker/insert flow; create metric list/detail; make rendered metric values openable; add unresolved-reference filter/review warnings.                                      |

## Work packages to defer

- Baselines, verification/validation, reports/dashboards, integrations, security administration, collaboration, product variants, and traceability matrix should wait for backend API contracts.
