# Frontend/backend mismatch analysis: reworked frontend requirements

## Scope

This analysis compares the reworked frontend requirements catalogue against the current backend requirements catalogue and the uploaded frontend source. PDF export has been removed from the frontend requirements. Metric placeholders are now specified as `[~MET001]`.

## Resolved mismatches

| Topic                   | Previous mismatch                                                                                                        | Current decision                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| PDF export              | Frontend first-release export stories mentioned PDF while the backend export adapter catalogue had no PDF adapter story. | Removed from frontend requirements. No frontend PDF export control is implemented. |
| AsciiDoc export         | Backend first release includes AsciiDoc, while frontend export requirements did not.                                     | AsciiDoc is now part of frontend first-release export controls.                    |
| Export format discovery | Frontend generated OpenAPI enums were too static for newly added backend adapters.                                       | Frontend now uses `/export/formats` at runtime and sends dynamic format IDs.       |

## Remaining mismatches and risks

| Topic                          | Frontend requirement                                                                                         | Backend/current-code state                                                                                                                                                                      | Risk                                                                                                                            | Suggested resolution                                                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Metric placeholder grammar     | Reworked frontend requirement uses `[~MET001]`.                                                              | Current uploaded frontend source and generated OpenAPI comments/patterns still reflect `[~MET-0001]` / `MET-0001`. The current backend-generated frontend client also exposes `^MET-[0-9]{4}$`. | Users and tests may still create old-style metric references until the backend contract and frontend metric helper are aligned. | Next backend+frontend package: align metric key regex, DTO docs, parser, tests, and migration behavior to `MET001`. |
| Export include/exclude options | FE-FR-IMEX-0001 says rejected/obsolete inclusion and metric/link rendering options are shown when supported. | Backend export options are still minimal and frontend only downloads discovered scopes/formats.                                                                                                 | First-release export UI is useful but not complete.                                                                             | Add backend option metadata and frontend option controls after API contract is explicit.                            |
| YAML                           | FE-FR-IMEX-0004 includes JSON/YAML controls.                                                                 | Backend YAML is backlog and frontend supports JSON download only through discovery.                                                                                                             | YAML controls should not be shown until backend exposes YAML.                                                                   | Keep YAML in backlog and rely on discovery.                                                                         |
| Generated export enum values   | Current generated models list `json` only for export format query params.                                    | Runtime backend supports `github-markdown` and `asciidoc` after the backend adapter work.                                                                                                       | Regenerating from an older OpenAPI document would not represent all adapters.                                                   | Keep runtime discovery and regenerate OpenAPI after backend docs include all adapter IDs.                           |
| Security/auth export scope     | UI offers all-project export when backend advertises it.                                                     | Backend authentication/authorization is still future work.                                                                                                                                      | In a multi-user system this may expose too much if backend authorization is missing.                                            | Hide or authorize all-project export once backend security is implemented.                                          |

## Conclusion

The export-format mismatch is now mostly resolved for the frontend: JSON, GitHub-flavored Markdown, and AsciiDoc are first-release frontend targets, and the UI uses backend discovery instead of hard-coded generated enum values. The main remaining cross-cutting mismatch is the metric grammar. That should be addressed before further metric UI expansion.
