# Complete frontend requirements catalogue

This document contains the complete revised frontend requirements list.

Every requirement includes:

- user story key;
- frontend requirement type;
- category;
- release assignment;
- area;
- complete user story;
- complete acceptance criteria.

## Identifier schema

```text
FE-<TYPE>-<CATEGORY>-<NNNN>
```

Where:

- `TYPE` is `FR` or `NFR`;
- `CATEGORY` is the stable frontend category code;
- `NNNN` is the four-digit sequence within the type/category combination.

## Authoritative layout model

- A persistent tab bar is shown at the top of the application.
- The first tab is the non-closable main workspace.
- The main workspace uses a left project sidebar and a right workspace pane.
- The sidebar contains `New Project` and the project list.
- The right pane contains module navigation, a contextual action bar where applicable, and module content.
- The initial modules are `Requirements` and `Categories`.
- The `Requirements` module uses a vertically resizable list/detail split view.
- The requirement list is shown in the upper pane.
- The selected requirement detail is shown in the lower pane.
- Requirement details can also be opened in closable full-screen tabs.
- Dedicated requirement tabs hide the project sidebar and module navigation.
- There is no `Back to requirement list` action.
- Initial startup loading is shown as a full-application overlay.
- After startup, loading and errors are shown in the affected right-pane content area.
- Requirement type is derived from category and is never selected independently.
